# Leave Management — Bug Documentation

## 1. Purpose

This document defines the standard format for reporting, tracking, analyzing,
and resolving bugs in the Leave Management module.

The purpose of bug documentation is to ensure that defects are clearly
understood, reproducible, prioritized, assigned, fixed, tested, and closed.


## 2. Bug Reporting Principles

Every bug should contain enough information for another developer or tester
to understand and reproduce the issue.

A bug report should clearly describe:

- What went wrong
- Where the issue occurred
- How to reproduce it
- What was expected
- What actually happened
- The impact of the issue
- The severity and priority
- The current status
- The person responsible for resolving it
- The verification result after the fix



## 3. Bug Lifecycle

A bug should follow a defined lifecycle.


Reported
   ↓
Triaged
   ↓
Assigned
   ↓
In Progress
   ↓
Fixed
   ↓
Ready for Testing
   ↓
Verified
   ↓
Closed
