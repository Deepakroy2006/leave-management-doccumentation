# Leave Management — Definition of Done

## 1. Purpose

The Definition of Done (DoD) defines the minimum conditions that must be
satisfied before a development task, feature, bug fix, or documentation
change is considered complete.

The purpose is to ensure that completed work is implemented, tested,
reviewed, documented, and ready for integration.

---

## 2. General Definition of Done

A task is considered **Done** only when:

- The required functionality is implemented.
- Acceptance criteria are satisfied.
- Required validation is implemented.
- Authorization rules are enforced.
- Relevant tests are completed.
- No known critical defects remain.
- Code follows project coding standards.
- Documentation is updated where required.
- Changes are committed to Git.
- Pull Request is created where applicable.
- Code review is completed.
- Approved changes are merged.

---

## 3. Requirement Completion

Before marking a task as complete:

- Requirement is clearly understood.
- User story is identified.
- Acceptance criteria are reviewed.
- Expected behaviour is implemented.
- Edge cases identified for the task are considered.
- No required functionality is intentionally skipped.

Example:

User Story
    ↓
Acceptance Criteria
    ↓
Implementation
    ↓
Testing
    ↓
Code Review
    ↓
Done
